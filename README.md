# Планировщик загрузки — тестовая версия 1.3.0

Внутреннее веб-приложение для формирования грузового пространства. Его возможности:

- выбор транспорта, контейнеров и полувагона;
- трубы с укладкой «в седло» и расчётом массы по диаметру, стенке и материалу, расчёт нужного числа машин;
- импорт пакинг-листов;
- 3D-расстановка мест с кантованием и штабелированием;
- контроль нагрузки на оси и общего веса;
- общий для команды список сохранённых планов.

Приложение работает **полностью внутри сети компании**: все библиотеки и шрифты лежат в пакете, обращений в интернет нет.

## Быстрый старт

```bash
git clone <адрес-репозитория> load-planner
cd load-planner
node server.js          # http://localhost:8080
npm test                # дымовые тесты сервера (необязательно)
```

Сторонние пакеты устанавливать не нужно: `npm install` не требуется.

## Что даёт GitHub

- **Проверка (`.github/workflows/ci.yml`).** При каждом пуше и pull request проверяется синтаксис и запускаются тесты сервера на Node.js 18, 20 и 22.
- **Docker-образ (`.github/workflows/docker.yml`).** Образ собирается в `ghcr.io/<владелец>/<репозиторий>` при пуше в `main` (тег `main`) и при создании тега вида `v1.0.0`. На сервере достаточно `docker pull` вместо сборки, см. комментарий в `docker-compose.yml`. Для приватного репозитория перед `docker pull` выполните `docker login ghcr.io` с персональным токеном с правом `read:packages`.
- **Демо на GitHub Pages (`.github/workflows/pages.yml`).** Публикует `public/` как статическую страницу. Включается в Settings → Pages → Source: GitHub Actions. В демо нет общего списка планов: планы хранятся в браузере и передаются файлом JSON. Для рабочего использования нужен сервер. **Учтите:** в бесплатном тарифе страница Pages доступна всем в интернете даже из приватного репозитория, поэтому для закрытых данных её не включайте или используйте GitHub Enterprise с ограничением доступа.
- **Шаблон замечаний.** Тестировщики заводят замечания через Issues → New issue → «Замечание по тестированию».

## Состав репозитория

| Путь | Что это |
|---|---|
| `server.js` | Сервер на Node.js без внешних зависимостей: отдаёт страницу и хранит планы |
| `test/` | Дымовые тесты сервера (`npm test`) |
| `.github/` | Workflows проверки, сборки Docker-образа и демо на Pages, шаблон замечаний |
| `THIRD_PARTY_NOTICES.md`, `licenses/` | Лицензии встроенных библиотек и шрифта |
| `CHANGELOG.md` | История изменений |
| `public/` | Само приложение (`index.html`) и локальные копии three.js, SheetJS и шрифта Golos Text |
| `data/` | Создаётся при первом запуске и не попадает в git: `plans/` хранит текущие планы, `history/` хранит прошлые версии |
| `examples/пример-пакинга.xlsx` | Пример пакинг-листа для тестировщиков |
| `Dockerfile`, `docker-compose.yml` | Запуск в контейнере |
| `deploy/loadplanner.service` | Служба systemd для Linux |
| `deploy/nginx.conf` | Обратный прокси nginx с паролем на вход |
| `deploy/iis-web.config` | Обратный прокси для Windows Server с IIS |
| `start.sh`, `start.bat` | Быстрый запуск вручную |

## Требования

- **Node.js 18 или новее** (рекомендуется 20 LTS). Устанавливать пакеты через npm не нужно.
- Либо Docker 20+ с docker compose.
- Браузер у пользователей: Chrome, Edge, Яндекс Браузер или Firefox последних версий, с поддержкой WebGL. Подходит любой ПК не старше 7–8 лет.

## Вариант 1. Запуск вручную

```bash
cd load-planner
node server.js            # или ./start.sh, на Windows start.bat
```

После запуска откройте `http://<адрес-сервера>:8080`. Порт меняется переменной `PORT`, например `PORT=9000 node server.js`.

## Вариант 2. Docker

```bash
cd load-planner
docker compose up -d --build
```

Приложение будет доступно на порту 8080. Планы сохраняются в `./data` рядом с `docker-compose.yml` и переживают пересборку контейнера.

## Вариант 3. Linux-сервер как служба (systemd + nginx)

```bash
sudo cp -r load-planner /opt/load-planner
sudo useradd --system --home /opt/load-planner loadplanner
sudo chown -R loadplanner: /opt/load-planner
sudo cp /opt/load-planner/deploy/loadplanner.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now loadplanner
sudo systemctl status loadplanner      # проверить, что служба запущена
```

Служба слушает только `127.0.0.1:8080`, наружу её публикует nginx. Блок из `deploy/nginx.conf` вставьте в конфигурацию сайта: приложение откроется по адресу `https://<портал>/loadplanner/`. На время теста там включён вход по паролю:

```bash
sudo htpasswd -c /etc/nginx/.htpasswd-loadplanner ivanov   # первый пользователь
sudo htpasswd /etc/nginx/.htpasswd-loadplanner petrov       # следующие пользователи
sudo nginx -t && sudo systemctl reload nginx
```

Приложение работает и из подкаталога (`/loadplanner/`), и с отдельного адреса: все пути внутри относительные.

## Вариант 4. Windows Server

1. Установите Node.js 20 LTS с nodejs.org.
2. Скопируйте папку, например, в `C:\Apps\load-planner`.
3. Запустите `start.bat`, чтобы проверить работу.
4. Чтобы приложение работало как служба, используйте NSSM:
   ```
   nssm install LoadPlanner "C:\Program Files\nodejs\node.exe" "C:\Apps\load-planner\server.js"
   nssm set LoadPlanner AppDirectory C:\Apps\load-planner
   nssm start LoadPlanner
   ```
5. Если нужен вход через IIS, используйте `deploy/iis-web.config`. Для него нужны модули URL Rewrite и ARR.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт сервера |
| `HOST` | `0.0.0.0` | Адрес; `127.0.0.1`, если сервер стоит за nginx или IIS |
| `DATA_DIR` | `./data` | Где хранить планы |
| `HISTORY_KEEP` | `20` | Сколько прошлых версий каждого плана хранить (0 — не хранить) |
| `MAX_BODY_MB` | `10` | Максимальный размер одного плана |

## Резервное копирование и обновление

- **Резервная копия:** достаточно копировать каталог `data/`. Это обычные JSON-файлы.
- **Восстановление плана:** если план удалили или перезаписали по ошибке, возьмите нужную версию из `data/history/<id>/` и скопируйте её в `data/plans/<id>.json`.
- **Обновление приложения:** выполните `git pull` (или замените `server.js` и `public/`), не трогая `data/`, затем перезапустите службу. Для Docker: `docker compose pull && docker compose up -d` либо `docker compose up -d --build`.
- **Выпуск версии:** поменяйте версию в `package.json`, `server.js` (`VERSION`) и `public/index.html` (`APP_VERSION`), допишите `CHANGELOG.md`, затем создайте тег: `git tag v1.0.1 && git push --tags`. Workflow соберёт образ с тегом `1.0.1`.

## Как устроено хранение

- **Общие планы.** Кнопки «Планы и файлы» → «Сохранить план» сохраняют план на сервере, и он виден всем пользователям. При каждом сохранении предыдущая версия уходит в историю. Если два человека сохраняют один и тот же план, остаётся последнее сохранение.
- **Черновик.** Текущий незавершённый план автоматически хранится в браузере пользователя, поэтому его не потерять при перезагрузке страницы.
- **Файлы.** Ведомость погрузки (CSV для Excel), снимок схемы (PNG) и план целиком (JSON) скачиваются как обычные файлы.

API для будущей интеграции с учётной системой:

```
GET    /api/health          проверка: {"ok":true,"version":"1.3.0-test"}
GET    /api/plans           список планов (без содержимого)
GET    /api/plans/{id}      план целиком
PUT    /api/plans/{id}      сохранить: {"name","summary","author","data":{...}}
DELETE /api/plans/{id}      удалить (копия остаётся в истории)
```

## Что проверить при тестировании

1. **Импорт.** Импортируйте `examples/пример-пакинга.xlsx`, затем свои реальные пакинги. Попробуйте вкладку «Из текста»: строки вида `Паллет, 1200, 800, 1440, 250, 5`. Проверьте, что столбцы распознались, а единицы и вес посчитались верно.
2. **Параметры транспорта.** Для каждого типа транспорта, который реально используется, в «Параметрах» внесите фактические данные:
   - габариты;
   - снаряжённую массу по осям;
   - положение шкворня и тележки;
   - допустимые нагрузки.

   Сейчас там стоят типовые значения, поэтому цифры по осям ориентировочные.
3. **Сверка с реальной погрузкой.** Сравните схему и нагрузки на оси с весовым контролем на 2–3 реальных отгрузках.
4. **Автоматическая расстановка.** Оцените её на смешанных партиях: листы, трубы и паллеты вместе. Отметьте случаи, когда кладовщик разместил бы груз иначе.
5. **Совместная работа.** Проверьте сохранение и открытие планов с разных компьютеров.

Замечания удобно собирать в таблицу с колонками: план, шаги, что ожидали, что получили, скриншот.

## Данные и конфиденциальность

Папка `data/` с планами исключена из git через `.gitignore`, поэтому реальные отгрузки в репозиторий не попадут. Если репозиторий публичный, не прикладывайте к Issues пакинги и планы с коммерческими данными.

## Известные ограничения тестовой версии

- **Расстановка.** Автоматическая расстановка жадная: она быстрая и предсказуемая, но не гарантирует оптимум.
- **Перемещение стопок.** Место, на котором стоят другие места, двигать нельзя: сначала нужно снять верхние.
- **Доступ.** Встроенных пользователей и прав нет, доступ ограничивается на уровне nginx, IIS или сети.
- **Порядок выгрузки** при нескольких адресах доставки пока не учитывается.
